# 第三轮优化讨论：从交付成本倒推协作设计

状态：Q1—Q4 已由用户确认，实施与本地验证完成，发布为 0.23.0。结果见[版本验证](./版本验证-0.23.0.md)。

## 已确定的约束

- Codex 负责关键决策和最终验收，也能接手代码；Claude 执行明确边界内的工作。
- 优先功能、便利性和降低不必要的主控消耗；不把复杂权限管理作为本轮主线。
- 保留新建、指定既有会话、原生终端与 Orca 工作流；默认中频。
- 主动回传、证据箱和资源收尾已在 0.22.0 交付。不能把已实现能力再次当作新功能规划。

## 第一性原理假设

用户购买的是可靠完成的工作。优化对象应包含规划、实现、等待、排障、返工、验收、收尾的总成本及人类介入时间。Codex 与 Claude 的 token 数或金额大小关系不能单独证明分工好坏。

确定性步骤应尽量由本地程序处理；Codex 主要处理需要取舍、改变方向或最终判断的事项。是否存在真实节省，需在同类工作与相同质量要求下比较。

## 设计树与当前讨论边界

1. 衡量方式：以验收通过工单的总成本和人工介入为主，还是只压低 Codex 用量。
2. 下一轮顺序：先建立少量真实业务基线，再决定优化项；还是根据当前代码先进行功能调整。
3. 基线结果之后：判断主要成本来自上下文重复、决策次数、执行方交付质量、失败恢复，还是工具调用步骤。
4. 针对主因选择改动，再确定任务边界、执行方自主范围、验收证据与效果判定。

第 1 项已确认：以每个验收通过工单的总费用为主，同时记录 Codex 费用、耗时、返工和人工介入次数。费用不可得时明确标为未知，不混用不同供应商的 token 单价。

第 2 项按用户调整：先做已有事实支持的基础优化，再提供一个迭代采集技能。用户在实际执行任务的 Codex 窗口运行技能，形成后续优化需要的证据；不要求先额外运行 3—5 个付费基线任务。

## 本轮实施范围（已确认）

### 基础优化

1. 合并可确定执行的准备步骤，唤醒时一次提供精简交付资料、版本和稳定性证明，减少重复查询。
2. 重要交付和求助保留待处理记录；普通进度允许合并。当前交付文件被覆盖不能等同于旧报告已处理。
3. 主控按报告标识返回处理结果，仅确认明确处理的项目，未处理项继续保留；区分收到、处理和验收通过。
4. 沿用原主控会话与现有三档交互，不在本轮更换主控上下文架构。上述调整的实际费用收益仍需真实任务证据。

### 迭代采集技能

- 在执行具体任务的 Codex 窗口调用一次，自动识别当前主控及关联 Claude 会话，默认采集当前任务的可用记录。
- 由本地程序提取用量、唤醒原因、空转观察、工具往返、回传到处理延迟、失败恢复、返工和人工介入；模型仅阅读汇总及必要异常片段。
- 区分实测、估算和未知。缓存输入、输出 token 分开记录；没有可靠价格或归属时不虚构费用及因果关系。
- 生成中文 Markdown 简报和结构化证据包，统一保存在本机复盘目录，并返回绝对路径。默认脱敏；不上传日志、不向其他聊天发消息、不自动改变业务会话。
- 后续在插件开发窗口读取证据包做迭代；生成文件本身不会自动唤醒该窗口。
- 技能和采集工具应支持 Windows、macOS。验证先用脱敏固定样本，真实任务采集以可访问记录为限。

## 本轮事实调查

只读检查唤醒上下文、确定性工具步骤及回传消费链路。代码事实与待验证推测分开记录。不会操作原业务会话或为调查启动模型任务。

### 已核对的代码事实

1. 唤醒使用 `codex exec resume` 续接原主控。提示虽短，仍复用原会话；不能由此断言每次实际输入全部历史，裁剪及缓存由宿主决定。候选优化是限制每次决策所需上下文，是否采用独立审查上下文须进一步讨论。
2. 配置与启用由调用方分两步操作。唤醒预读提供交付正文，但没有一起提供观察器的 `readyForReview` 稳定证明。可考虑把确定性准备步骤合成一次操作，并预装带版本的审查资料，减少重复查询。
3. 普通回传独立保存后，观察器依赖单个当前交付文件生成事件；短时间连续回传可能使旧报告变为 superseded。是否允许覆盖必须按报告类型定义，不能统一把被覆盖等同处理。
4. 主控输出批次 `handled` 时，当前实现确认整批事件，没有逐报告处理清单。`processed` 表示批次消费确认，不能证明每份报告都被阅读或业务验收。候选优化为明确逐项处理结果，未处理项留队列。

依据：`事件续接.mjs` 的 wakePrompt/dispatchWakeBatch、`协作策略.mjs` 的 handoff、`主动回传.mjs` 的 submitReport/reportReceipt，以及 `本地观察.mjs` 的交付观察逻辑。以上为只读代码事实，并非新复现的生产事故。
