# 续接故障与人类协同

## 人类操作保留管理

你在 Claude 中输入指令时，Codex 暂时停止发送，继续保留会话绑定和本地观察。人类一轮完成后才发协调事件，Codex 读取新增指令并理解它对任务的影响；等当前轮、人类队列、草稿和已知后台任务结束后接续。

| 情况 | 处理 |
| --- | --- |
| 人类正在输入或执行 | 保留观察，暂停 Codex 写入 |
| 人类指令完成 | 通知 Codex 理解新增意图，确认空闲后接续 |
| 旧任务被人类打断 | 保留历史，标为 interrupted_by_human，不自动重发 |
| 明确要求不再使用会话 | 解除绑定，原终端保留 |
| 明确关闭自动续接 | 保持停用，可主动查询和手动协调 |

Orca 用 `human_activity` 获取增量正文游标，接续用 `takeover`；原生后端用 `delegate_history` 和 `delegate_takeover`。所有操作按精确会话 ID 与原目录核对。

## 调度故障查看顺序

1. 调用 `delegate_wake`，`action=diagnose`，传当前 `controller_id`。
2. 优先看 `currentFault`，包含真实异常类型、代码、阶段、脱敏消息和有限堆栈；单记录失败列在 `recordFaults`。
3. 看 `observerHealth` 的阶段、心跳和过期状态。启用成功、进程存活和完整交付通知成功是三种不同证据。
4. 再核对 `lastRun`，用 `inspect` 查询具体 CLI 运行；标准错误只保存脱敏短摘要。
5. 看 `attention.notification` 的通知回执；`requested` 是已调用，`shown_by_os` 是系统报告显示，均不能证明人类已经阅读。失败会保留退出码和短错误。

当前调度故障拥有独立 ID，旧 CLI 错误的确认不能解除新的调度暂停。一个会话观察失败只对该记录退避，不阻断其他会话；恢复后更新原故障状态，再次失败会生成新的提醒。

**修复后的恢复入口：** `delegate_wake resolve_fault`，传当前 `fault_id`、修复依据 `resolution` 和 `decision=retry`。只确认故障用 `acknowledge`，保持暂停。有旧 CLI 运行待核对时先 `inspect/resolve`，再单独恢复调度故障。恢复保留待办和原配置；`enable` 只开启观察，不解除故障。查看 `effectiveState`、`paused` 和心跳确认真实状态。

这些诊断和普通观察都不调用模型。只有关键交付、求助和人类操作完成等事件进入协调轮。

## Orca重启与未发送草稿

Orca句柄随重启改变。发现 `terminal_handle_stale`／`binding_stale` 时先核对连接，重新列出终端，再用 `delegate_orca rebind` 按原 UUID 和原目录验证替代终端。原接入编号、指令、游标和交付关联保留；不用先释放旧记录，也不重开、重发任务。

未发送草稿的来源可能未知。`draft_blocked` 明确提示主控处理，`terminalBlocker` 提供存在性、长度和指纹，不输出原文到事件队列；指纹相同也不证明由谁输入。草稿不自动变为“人类接管”，握手遇到草稿也不会按 Esc。请用户选择保留、发送或清除，不能只等交付文件或声称是用户手动留下。

真实系统任务通知按来源字段识别，通知头用来清除对应已知后台任务；普通聊天引用相同标签仍按人类输入处理。

## 历史局限

旧版吞掉的异常详情无法追溯重建；补丁会明确标记“历史详情缺失”，保留原时间，不把旧 CLI 错误推定为新故障原因。修复通知编码不等于复现并消除了历史调度异常；后续具体异常需要以新增诊断为依据。

Windows 通知脚本由 Windows PowerShell 5.1 执行，因此非 ASCII 的 `.ps1` 使用 UTF-8 BOM；JSON 文件仍使用 UTF-8 无 BOM。[Microsoft 编码说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1)
