# 0.21.0 复盘修复与验证

本版依据用户的 2026-10-10 复盘及附件。原 Forge 代码、业务工单和主控聊天未追加任务；原始证据保留在本机，不进入公开发布包。

## 修复对照

| 现象 | 确认的原因／处理 | 验证与边界 |
| --- | --- | --- |
| Windows 多次 EPERM | 原子替换没有短暂占用重试；新增限时重试、文件写锁和提交前版本核对 | 注入短暂／永久错误；三进程150次更新；真实共享锁释放后5次尝试成功。不能凭此认定杀毒软件是原始原因 |
| Codex 占用后挂起 | CLI初始化失败与执行后失联混为一谈 | 精确初始化冲突且无线程／执行事件／用量才退避；有执行证据则继续保留不明状态；不会强占另一个写入器 |
| 后台幽灵任务、空结果 | 缺少任务ID与原子代理日志的结果渠道 | TaskOutput终态和通知只核销匹配任务；子代理原JSONL最终回复可取。没有终态的真实后台任务仍保留 |
| 自动化被认成人类 | 只看user类型，未识别官方压缩摘要及登记的命令来源 | 正文精确登记；原始命令、包装和stdout配对；官方双标志摘要独立分类。普通引用与未登记外部指令仍保守视作人类输入 |
| 输入状态不清、无法排队 | 普通发送与命令、接收与执行没有独立流程 | 排队存盘不声称发送；命令与普通任务分别核验；前一交付待处理时不自动越过；不明回执禁止重发 |
| 重读旧历史、消息limit失效 | 正文从全文开头读，消息上限没有实现 | transcript默认从本次指令开始、仅助手正文；history保留原能力，消息数与字符预算分别限制 |
| 验收后旧提醒仍在 | 人工验收没有事件处理回执，lastRun保留旧投影 | pickup只确认指定事件及匹配快照；投影显示已处理，原诊断保留；新交付不会被旧回执确认 |

## 本机实际回执

- **双会话完成→Codex处理**：两个新Claude UUID产生真实完成日志；同一次运行 `500b66a8-077d-48c1-aa73-daabf91a70eb` 收到两个 `instruction_completed`，CLI退出码0、目标线程匹配、结构校验通过。Codex实际读取两份回复，写出匹配两份口令和会话ID的验收文件；不是仅检查任务accepted。
- **排队压缩→下一指令**：独立会话中先持久化 `/compact` 和普通验证指令；配对命令UUID与stdout后确认commandState=completed，owner仍是codex；后续助手回复包含本次口令，两项队列都为completed。
- **Windows共享锁**：PowerShell持有只读共享句柄，另一个Node进程使用实际原子写入模块。5次替换尝试后写入revision=2，旧快照一直保留；输出通过。不复现原机器的具体外部占用者。
- **失败也保留**：首次命令实测发现压缩摘要误分类，第二次遇到Orca等待超时；修复并复验后才通过。Node测试进程中编排PowerShell共享锁曾以 `0xC0000409` 异常退出；原子替换已完成，但该测试编排不算通过。换为独立PowerShell持锁、Node写入，取得正常退出回执；该环境异常的深层原因未认定为连接器缺陷。

本地完整回归 **163项通过**；安装MCP接口检查与Windows真实PTY检查通过，均未调用模型。CI覆盖Windows、Ubuntu、Mac Apple Silicon和Intel，分别运行Node22/24，共8组；发布前核对实际结果，见[跨平台检查](https://github.com/lordfine/codex-claude-bridge/actions/workflows/test.yml)。真实Orca实测在Windows；Mac完整桌面Orca和共享应用整体重启没有在本机实测。旧业务会话的历史误判不会凭新版本自动清空，需按精确证据核对。

## 重现与检查

1. `node scripts/运行测试.mjs`：含文件占用注入、跨进程更新、写入器冲突、消息来源、后台任务、分页与排队防重发。
2. 用独立工作区、新Claude会话派发两条整批验证；启用同一个低频主控，保存每条的userUuid、firstAssistantUuid和completed。
3. 核对后台run确实包含两个完成事件，Codex实际读取成果并产生本次验收文件；只见workerReady或enable成功不算通过。
4. 用enqueue排队 `/compact 保留检查点` 与一条普通指令；核对命令配对stdout、普通任务首个助手记录、两项完成与owner。
5. 人工接住交付时用diagnose读取精确事件，再pickup记录处理依据与匹配交付版本，保留其他事件。

## 用量说明

双会话实测的一次处理轮：输入185271、缓存输入143360、未缓存输入41911、输出959。轮内有两次主会话正文入口选错，后续补了明确参数与当前轮默认分页；不能把这个样本当成修改后的最优用量，也不能用一次样本推算账单降幅。

本版减少旧历史读取、无变化模型轮及重复交付。关键决策仍按用户等级；低频不等于只看文件、不查连接，普通静默期由本地程序观察。
