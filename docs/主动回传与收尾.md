# 主动回传与收尾

本页说明 0.22.0 的主动回传能力。是否已加载，应以运行中的 `setup.service.executorReport` 为准，不能仅看磁盘源码。

## 派工与交付

执行中的补充证据用 `delegate_coordination` 的 `evidence` 操作，填写精确 task_id、backend、request_id、evidence_id 和短 text。重试保留相同编号与正文；改内容须换编号。`evidence_status` 区分 saved、read、acknowledged，不将保存当作执行端已采用。

Claude 在阶段边界或交付前调用 `inbox(request_id)` 读取，再用 `ack(request_id,evidence_id)` 确认采用。已有窗口可用回传 CLI 的 `--inbox` 和 `--ack 证据编号`。不注入未知终端草稿，不保证打断正在运行的工具，也不为等证据循环调用模型。

Orca 中确认为开发服务的已登记后台任务可用 `background_role`，指定当前 request_id、background_id、role=service 和 reason。一次性工作保持 work。服务继续保留且阻止清理；确认停止或已交接后，以原请求号及明确依据设为 released，解除资源保留。此操作不终止进程。

派工正文采用任务、范围、验收、交付四项。首次交接补充必要背景，返工只描述新增问题、证据和修复范围。模型、目录、请求编号优先使用工具参数。

新建 Orca 会话自动加载专用回传 MCP。已有会话不要求重启；派工说明会提供本轮 CLI 入口。原生托管在启用 `process_docs` 时接入回传。沿用现有模型配置，不修改 CCswitch。

执行端提交 `report_key`、`request_id`、`status`、`summary`，可附 `checks`、`unresolved`、`level`。状态包括 completed、blocked、needs_decision、progress。相同编号仅可重试相同内容；修订结果使用新编号。会话与目标主控由连接器绑定，执行端不能指定其他主控。

完成回传先保存，观察器确认当前轮结束和工作目录稳定后才投递交付事件。受阻和需决定的回传优先投递。模型漏报时继续用原会话日志和本地观察兜底。

收据分别表示已保存、待观察、已排队、主控已处理或被更新回传替代。主控处理不等于业务验收。主控可用 `delegate_coordination(action=report, report_id=...)` 读取某份不可变回传，避免用最新交付冒充旧事件。正式验收仍检查实际版本与证据。

## 等待方式

新长任务默认采用事件驱动，不同时创建 Goal 自动续接。现有公开接口尚未证实可让活动 Goal 静默等待外部事件；连接器不能靠一个等待字段停止宿主调度。已有 Goal 的状态不会自动改变。

低、中、高档都不因心跳或无变化超时调用模型。档位决定普通阶段交付的粒度，重大异常及时处理。`codex queue` 的命令返回仅证明消息已入队，本机隔离探测未因此观察到新主控轮次，不能将它当作已经验证的自动唤醒替代方案。

推荐将返回的 `statusCursor` 原样传给 `after_cursor`。游标包含类型、目标和运行实例；混用 overview、单任务或旧终端实例会报 invalid_cursor。旧字符串 after_revision 保留兼容，不具备完整的作用域校验。

## 会话与资源收尾

主控在交付后判断是否还需要原执行会话。确认无复用价值时，执行清理；无需把已完成的验证终端长期留在 Orca。

- Orca：`cleanup` 默认预览，执行时传 `no_reuse_confirmed=true`、简短 `summary` 和 `dry_run=false`。只处理连接器自建会话，核对原 UUID、终端实例、执行状态和队列后关闭终端，并退役观察记录。已有用户会话默认只交还管理。
- 当前 Orca create 在既有目录中创建终端，没有创建该目录或分支的所有权，所以 cleanup 保留该目录和分支。不能凭“终端由连接器创建”删除整个项目。
- 主控另行创建的 Orca 专用工作区，应记录工作区 identity、路径和分支。确认不再复用、成果已合入或属于明确可丢弃的测试产物后，通过 Orca 官方工作区删除入口收尾，再复查目录和分支。此步骤由主控执行，当前 cleanup 不会自动推断外部创建目录的所有权。
- 原生托管：归档时传 `cleanup=true` 和 `no_reuse_confirmed=true`，可清理已合入且干净的专用工作树，并以非强制方式删除自建分支。已知过程文档先留档；其他未提交、忽略文件或未合入成果会阻止清理。
- 清理回执明确列出关闭、移除和保留的资源；未完成清理不伪装成功。历史与简短交付依据保留，关闭终端不等于抹去历史。

## 尚未覆盖的边界

屏幕菜单分类提供诊断提示，不能独立成为批准操作的依据；截图里的秘密仍需专门处理。当前轮的主动推送补充证据、常驻后台服务角色对账，以及活动 Goal 的宿主级等待仍需后续独立验证。不能据此声称复盘的 20 个场景已全部通过。
