# 一次调用，收集下轮迭代需要的证据

## 怎么用

在实际指挥 Claude 干活的 Codex 窗口输入：

> 使用 $claude-code:bridge-retrospective 复盘这次协作，生成连接器迭代证据包。

显示名称为“桥接复盘”，技能标识为 `bridge-retrospective`，随插件一起安装，Windows 和 macOS 共用。若安装后没有出现，重新加载插件或重新打开 Codex，让技能目录重新发现。

技能自动使用当前 Codex 主控 ID，关联它管理的 Claude 会话。无需重新接管，也不会给执行会话发送消息。输出保存在用户目录下 `.cache/cc-plugin-codex/迭代复盘/`，每次单独建目录，返回绝对路径。

- `复盘报告.md`：供人阅读的短摘要。
- `证据包.json`：供后续开发读取的统计、覆盖范围和证据指针。

把证据包的路径发给插件开发窗口，就能继续迭代。本技能不会自动唤醒其他窗口或上传文件。更换电脑时需要你自行提供文件。

## 能看出什么

| 指标 | 依据与边界 |
| --- | --- |
| Codex 用量 | 本地累计 token 的变化，缓存输入、输出分列；回退或缺失不伪造 |
| Claude 用量 | 同消息 ID 去重，主会话与可访问子代理分别汇总；缓存读写分列 |
| 观察候选 | 工具白名单筛选的观察轮，供核对；不能直接认定浪费 |
| 工具往返 | 调用次数和输入输出字节；字节数不是 token |
| 回传延迟 | 报告保存到精确处理回执的时间；未处理项不造时间 |
| 故障恢复 | 调度故障、恢复记录、运行状态；原始错误正文不导出 |
| 返工、人工介入 | 不完整归因时未知；有托管流程时另列累计返工记录 |
| 每个验收工单费用 | 当前无完整账单与归属时未知；不套公开 API 价格估算订阅或 CCswitch 账单 |

既有 Claude 会话默认统计可能包含接入前的记录。比较特定任务时说清起止时间，例如“只复盘北京时间今天 14:00 到 16:00”。技能换算为带时区的 ISO 参数。边界可能横跨一个模型轮；轮次零不表示期间没有用量。

## 为什么采集不会再读一大遍日志

本地 Node 程序逐行解析日志，只把统计交给 Codex。原始聊天、命令、工具参数、凭据、完整路径和错误正文均不复制到证据包；保留会话与报告标识、来源编号、行号和内容摘要哈希用于定位。本机日志存在性、大小限制和解析失败都会在覆盖说明中记录。

采集程序不调用模型，使用技能的 Codex 本轮仍有正常用量。无日志时生成有限报告，不能根据零计数推断“没有发生”；不会猜选其他会话。日志按流读取，单份最多读取 512 MiB，超出明确标记截断。

## 基础协作优化

`delegate_wake(start)` 合并配置与启用；保留旧接口，已有故障仍要按编号恢复。续接一次带齐每份报告、原请求和新鲜的稳定性证明，减少机械补查。

重要报告独立保存和观察，“当前交付.md”只作快照。普通 progress 回传不唤醒模型；completed 依档位和交付级别入队，blocked／needs_decision及时处理。更新前旧格式报告可补入观察。

续接结果逐项确认事件。遗漏或 deferred 保留并暂停供核对，避免错误地清空整批报告，也避免无效自动重试。业务验收仍由 Codex 核对实际文件与要求。
