# 功能与限制

## 原生托管

- 可恢复工作流：规划、实现、独立审查、最多两轮返工、Codex 验收合并。
- 可见窗口、增量正文和事件、会话别名、批量操作、归档恢复与精确 UUID 续接。
- 每个 Codex 主控默认并发 3 个顶层会话，可调至 10，超额排队；子代理不占顶层配额。
- 默认不限执行时长；用户可为单个会话指定最大持续时间（`max_minutes`，`0` 表示不限时）。默认 120 主轮，可调整；子代理并发默认 8、最高 20。
- 当前 Claude／CCswitch 模型配置，角色偏好与单次覆盖。
- 普通操作本地处理，敏感门禁和人工交接；失联不自动放行敏感操作。
- 关键事件持久排队，Codex CLI 按精确存储会话 ID 串行续接；忙碌或状态不明时等待。

这些能力由 [托管模块](../plugins/claude-code/scripts/lib/managed-service.mjs)、[协作流程](../plugins/claude-code/scripts/lib/managed-workflow.mjs) 和 [事件续接](../plugins/claude-code/scripts/lib/事件续接.mjs) 实现。

## Orca

支持列出、接入、新建、发送、状态、屏幕／正文读取、等待、释放和关闭。接入须绝对工作区、精确 Claude UUID及人类队列空闲确认，核对真实终端身份后操作。

稳定请求去重；运行时、终端实例或会话变化时停止派发，不自动重开或双发。`release` 保持原终端存活。已确认完成以会话正文为准，不能只看终端空闲或输入接收回执。

本地观察器可将完成、失败和求助送入事件队列，通过 Codex CLI 续接。尚未接入原生后端的工作流、统一配额和预算、独立工作树及审查合并。权限与钩子保持原会话配置。[Orca 模块](../plugins/claude-code/scripts/lib/Orca会话.mjs)

## 分档协作与读取

默认中频，主控配置与单任务覆盖支持低／中／高三档。所有档位保留关键异常升级，无变化不调用模型；阶段交付按身份和稳定快照核验。历史正文按目录＋精确 UUID 只读分页，实时状态和屏幕读取保留。必要轻量同步使用 `low`，关键 CLI 轮恢复捕获或用户设置的深度等级。[使用与边界](./协作档位与用量.md)

## 0.19 的协作与平台修复

新增统一短摘要 `delegate_overview`，共25个工具。审批默认等主控5分钟，可用 `permission_wait_seconds` 调整；超时转人工且原记录可查，失效钩子不补写批准。审查取消返回待处理，退出状态清理活动标志。

默认不限时。有执行预算时，明确审批、空闲和人类控制暂停计时；旧记录无法可靠重建的等待时间不追溯扣除。Orca通知边界可只读诊断并显式修复，控制权不自动更改。完整系统包装兼容识别不是密码学认证；未知边界继续保留人类保护。

Mac支持原生Terminal与Orca新建，采用可执行路径解析、短Unix socket和POSIX进程查询。[Mac说明](./Mac安装与验收.md) · [本次验证](./版本验证-0.19.0.md)

## 验证口径

0.19.1 保留人类临时操作期间的管理绑定，完成事件进入协调队列，接续时推进已处理的人类边界。新增 `delegate_wake diagnose`、观察心跳、独立调度故障与通知回执。[协同与排障](./续接故障与人类协同.md)；历史异常未保存的详情无法追溯重建。

基础版本在 Windows 的 Claude Code 2.1.291、自定义 `glm-5.3-flash` 配置和 Orca 1.4.220 下，验证过已有／新建会话的实际文件写入与正文验收。0.18.0 包含 106 项自动回归；新增实机范围与技能对照结果见 [版本验证记录](./版本验证-0.18.0.md)，不等同于所有场景实测。

自动检查见 [GitHub Actions](https://github.com/lordfine/codex-claude-bridge/actions/workflows/test.yml)；当前检查入口为 [运行测试](../scripts/运行测试.mjs)，只覆盖公开接口，未保留废弃咨询接口测试。

原打开 Codex 桌面窗口即时刷新、远程 Orca、其他平台可见终端、长期多主控并发和全部人工输入竞态仍未完成实机验收。模型调用量因上下文和缓存变化，不保证总 token 必然更低。

Windows 的准备检查当前通过 `claude.cmd` 调用 Claude；原生 `claude.exe` 安装形态尚未适配这项检测。[检测实现](../plugins/claude-code/scripts/lib/managed-readiness.mjs)
