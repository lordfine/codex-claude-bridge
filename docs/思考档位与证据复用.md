# 分别调整交互频率和思考投入

默认是**中频＋中思考**。可以直接对 Codex 说：

> 这个任务用低频、低思考；明确的小任务交给子代理，整批完成后再验收。

频率决定何时找主控，思考决定处理工作时投入多少推理。两个参数独立，不因提高思考而增加通知，也不因降低频率跳过重大异常。

| 频率 | 低思考 | 中思考 | 高思考 |
| --- | --- | --- | --- |
| 低 | 明确批量小改动 | 常规功能自主完成 | 复杂长任务，集中判断 |
| 中 | 简单多步骤任务 | 日常研发默认 | 跨模块改动与关键审查 |
| 高 | 快速交互小改动 | 探索式开发 | 高难度交互排障 |

低频低思考优先节省投入，但返工可能抵消节省。子代理只接收自己工作需要的上下文，主代理汇总短报告；小改动直接完成。默认子代理硬上限仍为 8，可调至 20，实际数量根据独立任务决定，不要求开满。

## 配置与实际生效

`delegate_coordination(configure)` 分别传 `profile` 和 `thinking`，值为 low／medium／high。单任务使用 action=profile 或 thinking，传精确 task_id 和 backend；inherit 回到主控默认。已有明确配置保留。

`escalate` 携带当前 request_id 和 reason 临时升一档，最高到 high；`restore_thinking` 恢复原档，换请求后旧升档失效。普通同步始终低投入。保持最多两轮修复后主控接手的约定。

新原生与 Orca Claude 会话通过 `--effort` 设置主代理，并通过 `--plugin-dir` 加载会话专用的低、中、高投入代理。插件目录放在桥接运行状态中，不安装到用户全局、不改 CCSwitch 供应商配置。版本、环境变量和模型能力会影响应用；建议使用本次验证版本 Claude Code 2.1.291 或兼容更新版本。

状态区分：launch_configured 为已构造参数；cli_observed 为启动界面显示了档位；pending_restart 为策略已保存但当前进程未应用；not_applied 为既有外部会话尚未应用。CLI 显示档位也不能证明第三方网关实际遵守。

自动 Codex CLI 续接传入档位并核对可读运行记录。正在生成的桌面轮无法即时切换。活动 Claude 继续工作，需要重启的调整由用户选择。

## 检查只做需要的部分

实现者记录源码、环境身份、检查范围、命令、结果、证据与未覆盖项。主控通过 `record_check` 登记，`reuse_check` 核对一致性。环境身份由调用方声明，应包含数据集、服务、数据库或运行时等相关信息；连接器不读取凭据，也不执行登记命令。

源码、环境、范围、命令一致且原检查通过时，返回 reusable=true。记录属于执行方声明，仍需核对证据。源码变化、失败、证据不足、范围扩大和高风险时补验；必要全量与部署检查保留。

低中高档的交付预读采用不同摘要预算，未解决事项保留，需要完整报告时使用预装参数展开，减少重复全文读取。

## 用复盘确认效果

在原任务窗口运行 `$claude-code:bridge-retrospective`。新采集器区分独立事件、重复尝试、已证明的模型执行及归因未知轮次，递归统计子代理日志。费用无可靠价格时保持未知，不承诺固定节费比例。[采集说明](./迭代复盘.md) · [版本验证](./版本验证-0.24.0.md)
