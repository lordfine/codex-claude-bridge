# 思考等级与协作成本优化讨论

状态：Q1—Q6及整体实施已获用户确认，源码和本地验证已完成，发布目标0.24.0。结果见[版本验证](./版本验证-0.24.0.md)。

## 来源与目标

依据用户提供的本机迭代复盘目录 `2026-10-11T10-20-57-473Z-01a11b04-224e364d` 中的《流程效率与成本分析.md》《证据包.json》，交叉阅读《复盘报告.md》《主控工序统计.json》。统计窗口为北京时间 2026-10-09 00:00 至 2026-10-11 18:20 左右。

沿用此前确认的目标：降低每个验收通过工单的总成本，同时观察耗时、返工和人工介入。用户提出增加独立于交互频率的思考等级，并让低档执行更主动地使用子代理。

## 两个参数的候选定义

- **交互频率**：主控在什么工作边界介入。沿用低频的完整批次、中频的里程碑、高频的约定子任务；重大异常和必需决策不被静默。
- **思考等级**：处理一个工作单元时使用的推理投入。候选为低、中、高；同时记录请求等级、实际应用范围及验证状态。
- **执行策略**：任务拆分、子代理职责、上下文范围和证据复用。可以随档位提供默认建议，但不与模型实际思考参数混为一谈。

第三方模型是否真实支持思考参数必须单独核验。提示词要求“少思考”不等同实际参数已生效。保留 CCSwitch 当前配置与用户模型名称，不随档位擅自切换供应商配置。

## 组合草案

| 频率与思考 | 低思考 | 中思考 | 高思考 |
| --- | --- | --- | --- |
| 低频 | 明确批量改动，候选最省成本模式；完整批次交付 | 清楚边界的常规功能，自主推进后集中验收 | 复杂但边界已确定的长任务，少打扰、集中深度判断 |
| 中频 | 简单多步骤工作，在里程碑纠偏 | 常规研发默认候选 | 跨模块改动，在关键里程碑深入审查 |
| 高频 | 人类紧密参与的小改动，每次快速反馈 | 探索式开发，频繁调整方向 | 高难度交互排障；控制范围，避免全程高投入 |

此表是场景建议，不是成本排行榜。低频低思考可能因遗漏和返工变贵；高频低思考也可能因重复上下文超过低频高思考。相同验收要求下的总费用才是比较依据。

子代理用于隔离明确工作所需的上下文。建议低档更积极委派边界清楚的子任务，同时控制并发和重复阅读；简单任务由主代理直接完成。暂不修改此前默认 8、最高 20 的子代理并发设置。

## 官方能力依据

- [Claude Code 模型配置](https://code.claude.com/docs/en/model-config)：提供会话思考设置；模型能力和设置优先级影响实际应用。
- [Claude Code 子代理](https://code.claude.com/docs/en/sub-agents)：子代理定义可设置 effort；环境变量 CLAUDE_CODE_EFFORT_LEVEL 优先于子代理设置，逐次调用参数还有版本要求。因此不能用一个全局变量实现主子独立升降档。
- 当前插件已有自动 Codex CLI 轮的轻量与深度思考设置；它不能即时改变正在执行的桌面轮。

## 当前代码的已确认边界

1. `协作策略.mjs` 与 `事件续接.mjs` 已区分轻量同步 low 和深度续接 inherit，并通过 Codex CLI 参数设置自动轮的思考等级，记录请求档位和可读取的实际档位。新功能应复用该路径。
2. 原生 `managed-broker.mjs` 与 Orca 创建命令仅选择 Claude 模型，尚未传入主代理 effort；子代理也没有独立 effort 配置。因此现有低频不等于 Claude 低思考。
3. 原生托管把子代理并发上限传入进程环境；Orca 路径尚未暴露同等参数。原生参数被传入也不等于已实测每种 Claude 版本均会遵守。
4. 既有 Orca 会话可保留原进程接入，不能通过修改启动参数追溯改变该进程。需要另行确定运行时设置方法及回执，不能返回虚假的应用成功。
5. 当前协作频率是交付事件门槛。文档中的观察缓存 60／15／3 秒不表示模型调用间隔；缩短或延长缓存不能替代正确的工作批次拆分。

### 已确认的采集缺陷与解释限制

- `迭代采集.mjs:78` 至分类逻辑只识别外层工具名，实际 exec 包装以及 wait／sleep 名称匹配不全，造成观察候选漏记。无法从汇总包反算真实漏记轮数。
- `迭代采集.mjs:121` 的子代理发现只扫描单层目录，不覆盖递归工作流日志。需要递归发现，同时避免路径别名和请求重复造成反向高估。
- `迭代采集.mjs:165` 的 wakeReasons 累加每次运行携带的事件；deferred_busy 保留事件重试，因此该数不是去重事件数。应分别展示独立事件、调度尝试及真实模型执行。
- `迭代采集.mjs:153` 的时延使用报告到确认时间，包含实际处理过程；21 份 pending 为非 progress 且尚无匹配确认的报告，不能直接判为漏接。
- 续接状态 acknowledged 也可能来自人工确认，不能据此证明自动续接真正执行成功。历史异常缺少版本及详细根因，需增加脱敏诊断信息再归因。

优先顺序建议：补齐统计覆盖和去重；分离排队与执行时延；缩减重复上下文和重复验证；新增思考档位与实际生效核对；最后比较同类任务、相同验收标准下的总成本。

## 第一轮已确认

1. 新等级同时指导 Codex 自动续接、Claude 主代理和子代理，困难时允许局部升档并记录原因。当前桌面轮或第三方模型无法控制的部分明确展示未生效或未验证。
2. 低档更主动委派边界明确的子任务，同时控制拆分和并发开销；简单任务直接完成。目标是总成本下降，不机械增加子代理。
3. 源码、环境、检查范围一致时复用可核验检查记录。Codex 核查关键逻辑并按需抽验，变化、失败、证据不足或高风险时补验，保留必要全量和部署检查。

## 第二轮已确认

4. 新主控默认中频＋中思考，支持主控默认和单任务覆盖；已有明确配置保留，用户选择新档后应用新映射。
5. 普通同步低投入；明显复杂决策或重复失败时，相关工作临时升一档，最高到高。记录原因，处理完恢复原档；沿用两轮修复后主控接手的规则。
6. 已有会话等当前轮和人类指令队列清空后应用会话级设置；无法验证时明确显示生效范围，保留原设置继续工作，需要重启的调整由用户选择。

子代理数量暂沿用现有可调上限，根据任务独立性和额外上下文开销安排实际并发，不额外引入固定数量矩阵。

## 本轮实施方案

### 独立的思考档位

- 增加低、中、高思考档，独立于交互频率；新主控默认中频＋中思考，支持主控默认与单任务覆盖，保留已有明确配置。
- 主代理、子代理和 Codex 自动续接按工作阶段应用相应档位；普通同步维持低投入。复杂决策或反复失败的具体工作临时升一档，最高到高，处理完恢复并保留原因记录。
- 自动续接复用现有 Codex CLI 思考配置能力；桌面正在执行的轮次无法即时改变时如实展示。
- Claude 新进程采用受支持的会话级设置，子代理使用受支持的独立设置。逐次调用参数和配置定义按实际版本能力选择；不使用会覆盖所有子代理的全局变量冒充主子独立控制。
- 既有会话等当前轮及人类队列清空后应用可验证的会话级设置。无法应用时继续工作并展示限制，重启续接由用户选择。
- 各执行层分别记录请求档位、应用方式、可观察实际档位及验证状态。Claude CLI 接受设置与第三方网关模型遵守设置分开说明，不修改 CCSwitch 供应商配置。

### 减少重复上下文与重复检查

- 更新协作技能与派单资料，以目标、边界、交付和检查要求构成短任务说明；避免重复主控背景和全文历史。
- 低档积极委派明确子任务，由主代理汇总短报告和来源证据；简单工作直接完成，实际并发按独立性与额外上下文开销安排，沿用现有上限。
- 检查记录绑定源码指纹、环境、命令或检查范围、结果及未覆盖项。相同条件下复用，变化、失败、证据不足和高风险时补验；复用不自动构成业务验收。
- 控制交付阅读体积，保留精确历史与实时增量读取能力，以及按需展开完整证据的入口。

### 修复采集与补齐调度诊断

- 保守识别 exec 等包装内的工具调用及实际等待工具名称；不能确认的轮次标为未知，不判成零观察或全部浪费。
- 递归发现子代理和工作流日志；按来源与稳定请求身份去重，流式分段用量保留正确累计方式。范围及缺失单列说明。
- 唤醒统计拆成唯一事件、调度尝试、真实模型执行与人工确认，不把重复重试当成新事件。
- 报告区分排队、领取、处理与验收，待处理按类型和请求生命周期分类；缺失时间不伪造可分解的等待时长。
- 增加故障的运行版本、阶段、去重身份和脱敏诊断摘要；调查可复现的调度缺陷再修复，历史证据不足的故障保持待证实。
- 主控忙碌期间由本地程序退避保留交付，不擅自暂停用户 Goal，不靠增加模型轮处理无变化状态。

## 验收与交付

1. 使用脱敏固定样本验证包装工具分类、递归日志覆盖、请求去重、唤醒计数与报告状态，展示修正前后的口径差异。
2. 验证九种频率与思考组合的参数独立性、覆盖顺序、局部升档及恢复、旧配置兼容；桌面与不支持的第三方能力必须明确报告限制。
3. 在独立新测试会话验证参数应用、交付回传与 Codex 真实处理，检查实际运行证据；不操作正在运行的 Forge 业务会话。
4. 复用检查证据的有效条件与失效条件均需覆盖；不得因复用跳过必须的风险检查。
5. 检查 Windows 与 macOS 平台路径和参数兼容。没有可用 macOS 实机或第三方网关请求证据时，说明验证层级，不冒充完整实测。
6. 同步更新协作技能、复盘技能、用户文档及版本验证记录。先证明功能和统计正确，再用真实同类任务评估成本；不预先承诺节费百分比。

依 grill-with-docs 技能，在用户确认以上共同理解后进入实现。实际修复清单与尚未证实的历史异常在最终交付中分别列出。
