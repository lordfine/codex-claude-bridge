# 快速开始

## 准备与安装

确保 Claude Code 使用当前配置能正常工作。需要 Node.js 20+、Git 和 Codex。原生托管窗口在 Windows 使用 Windows Terminal、PowerShell 7；Orca 新建要求 Orca 正在运行、目录已注册为工作区。

```powershell
git clone https://github.com/lordfine/codex-claude-bridge.git
cd codex-claude-bridge
codex plugin marketplace add .
codex plugin add claude-code@codex-claude-bridge
```

下载 Release 用户可解压后进入市场根目录，执行后两条命令。根目录包含 `.claude-plugin/marketplace.json`。安装后重新加载 MCP 实例，让 Codex 调用 `setup`；默认不调用模型。首次准备原生托管终端在插件缓存安装依赖，需要 npm 与网络。

## 使用

给 Codex 绝对工作区目录、目标和验收条件。新实现工作默认在独立工作树进行，Codex 通过 `delegate_workflow` 保存阶段，安排审查和至多两轮返工，最后核对实际代码并验收合并。

用户可以在可见 Claude 窗口输入；`/交还` 交回控制权。默认接管等当前轮与人类队列结束，明确要求“立即接管”才中断。`Ctrl+D` 关闭显示客户端，后台继续；可以重开窗口。

后台模式由 `delegate_wake` 配置，关键事件触发 Codex CLI 按精确存储 ID 续接，普通进度不启动模型。当前打开桌面窗口即时刷新仍未验证。

## Orca

接入时提供原绝对目录与精确 Claude UUID，确认当前轮、人类队列已结束。Codex 在空闲窗口执行本地 `/status` 身份握手；有草稿或弹窗时停止注入。

新建时由 `delegate_orca(create)` 在给定工作区打开原生终端，随后发送任务。首次信任或 MCP 配置弹窗由用户处理。模型可使用当前配置槽位或实际名称；插件不改 CCswitch。

`accepted` 只证明输入接收；`logged/completed` 根据对应 Claude 会话正文核对。回执不明时先查状态，不重复派发。`release` 保留原终端；关闭用户已有终端必须明确授权。

Orca 当前未接入独立工作树、原工作流、统一预算和自动唤醒。[功能与限制](./功能与限制.md)

## 更新与迁移

本地市场目录 `git pull` 后重新安装插件并重新加载 MCP 实例。固定版本用户从新 Release 解压，再注册市场目录。

旧插件与本项目包含同名 `claude-code` 工具。从旧项目迁移须停用旧插件，再加载本项目；不可同时启动两套主控去操作同一 Claude UUID。本地状态及兼容环境变量保留原名称，避免破坏已有会话。迁移不改变已有任务预算和模型设置。

新工具不出现时核对安装版本并重新加载实例。缓存安装被 Windows 占用时，先停止对应 MCP 实例再安装，不删除会话数据。Orca 无法识别身份时核对目录、UUID、CLI 运行时及草稿／弹窗；不使用最近会话代替精确目标。
