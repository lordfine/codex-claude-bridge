# 第一次使用

**推荐路线：Windows + 普通终端托管。无需安装 Orca。**

## 1. 先认识几个名字

| 名称 | 在这里的作用 | 是否需要 |
| --- | --- | --- |
| Codex | 你交流的主控，负责规划与验收 | 需要 |
| Codex CLI | 本文用来安装插件，也用于可选后台续接 | 本文命令需要 |
| Claude Code CLI | 接收任务、操作代码的执行工具 | 需要 |
| Node.js | 运行本地桥接器 | 需要，20+；CI 覆盖 22／24 |
| Git | 管理代码、分支和独立工作目录 | 需要 |
| Windows Terminal、PowerShell 7 | 显示和启动普通托管窗口 | Windows 普通窗口需要 |
| Orca | 集中管理项目和多个 AI 终端的桌面工作台 | 可选，只在 Orca 路径需要 |
| CCswitch | 如果你已经用它管理供应商／模型配置，继续沿用 | 可选 |

Claude Code 是执行工具的名字。执行模型来自你当前配置，并不要求你使用固定的 Anthropic 模型名称；第三方模型能否正常工作，先在 Claude Code 中单独确认。

## 2. 检查已有环境

在 PowerShell 中执行：

```powershell
node --version
git --version
codex --version
claude --version
pwsh --version
```

命令找不到时，先安装对应工具或修正 PATH。`pwsh` 指 PowerShell 7；系统自带的 Windows PowerShell 与它不同。Windows 普通窗口还需要可以运行的 Windows Terminal。

官方安装入口：[Codex CLI](https://learn.chatgpt.com/docs/codex/cli)、[Claude Code](https://code.claude.com/docs/en/overview)、[Node.js](https://nodejs.org/en/download)、[Git](https://git-scm.com/install/windows)、[PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)、[Windows Terminal](https://learn.microsoft.com/en-us/windows/terminal/install)。Orca 的可选入口见下文。

先单独启动 Claude Code，完成现有登录／连接配置并得到一次正常回复。不要把密钥贴到对话或 Issues。本插件继承当前配置，不负责更换供应商或设置 CCswitch。

## 3. 安装桥接插件

```powershell
git clone https://github.com/lordfine/codex-claude-bridge.git
cd codex-claude-bridge
codex plugin marketplace add .
codex plugin add claude-code@codex-claude-bridge
```

也可以下载 [发布源码包](https://github.com/lordfine/codex-claude-bridge/releases/latest)。解压后进入包含 `.claude-plugin/marketplace.json` 的市场根目录，执行后两条命令。

安装后按 Codex 客户端的方式重新加载插件；如果新工具没有出现，关闭并重新打开 Codex，再对它说：

> 检查 Claude 协作插件的环境，先不要派发任务。

对应 `setup` 默认不调用模型，检查 Claude 命令、当前模型配置和终端依赖；首次会准备 `node-pty`，需要本机 npm 与网络。成功表示环境准备通过，真实模型是否可用仍以实际回复为准。

## 4. 完成第一个小任务

使用一个小型 Git 仓库，先保存当前改动。把绝对路径交给 Codex：

> 工作区：〈绝对路径〉。
> 使用普通终端托管 Claude，只修改 README，补充安装依赖和启动步骤。
> 不要改业务代码，不安装新的业务依赖。
> 完成后由你核对改动与现有脚本是否一致，先不要合并。

你应当能看到一个 Claude 可见窗口。新实现工作在独立工作树进行，因此原目录不一定立即出现改动；可以让 Codex“告诉我执行目录并查看差异”。

查看进度或追加要求时，继续对同一个 Codex 主控说话：

> 看看这项任务进度。请追加：把 Windows 的启动方式也写清楚。

Codex 检查实际结果后，再由你决定是否合并。跑通这一轮后，换成真正的功能任务，并写清验收条件。

## 5. 什么时候使用 Orca？

如果你已经在 [Orca](https://www.onorca.dev/) 中运行多个 Claude 会话，或希望集中观察终端与代码差异，再使用它。[官方终端说明](https://www.onorca.dev/docs/terminal)

**接入已有会话：**

> 工作区：〈Orca 已注册目录的绝对路径〉。
> Claude 会话编号：〈精确 UUID〉。
> 当前轮和人类队列已结束，请接手这个 Orca 会话，先读取状态。

Claude 会话 UUID 可在目标 Claude 的 `/status` 中查看。它不是 Codex 聊天 ID，也不是 Orca 终端句柄。接入时插件再次核对身份，不需要你退出原进程；有草稿或弹窗时先处理它们。

**新建会话：**

> 在 Orca 的〈已注册工作区〉新建 Claude 会话，执行〈具体任务〉，完成后核对结果。

Orca 须正在运行，工作区须已注册；首次信任或 MCP 弹窗在 Orca 中处理。当前插件在给定目录启动，不自动创建独立工作树。

Orca 支持本地观察和事件续接；完整工作流、统一预算和自动合并尚未接入。它自身具备的功能与本插件已接上的能力需要分别理解。[功能与限制](./功能与限制.md)

## 6. 选择协作频率

不指定时采用中频。可以说“主控默认低频，这个排查任务单独高频”。档位绑定 Codex 主控任务，重开窗口沿用配置；修改影响后续事件。

> 开启后台事件续接，按中频协作。让 Claude 完成约定里程碑后交付；普通明确错误自行修复，重复失败或需要决策及时升级。保存阶段说明后结束当前 Codex 轮。

新版插件自带 `consult-claude` 技能，无须重复安装另一份同名技能。技能会指导 Codex 按需取工具、读取短交付和新增正文。[详细说明](./协作档位与用量.md)

## 常见问题

**没有 Orca，完整协作还能用吗？** 能，普通终端托管提供实现、独立审查、返工和验收合并。

**指定 `glm-5.3` 就一定可用吗？** 只有你的当前 Claude 配置包含该实际名称或对应槽位时才可用。先让 Codex 读取可用模型，再选择；不要照抄别人的模型名。

**Claude 说完成了，为什么还没合并？** Codex 需要核对实际改动和验收条件；如果你要求先不要合并，它会停在检查阶段。

**已有普通终端会话能直接接手吗？** 非 Orca 外部进程需先退出，再按原目录和精确 UUID 续接；不要同时启动两个进程写同一会话。

**Claude 完成能自动叫醒 Codex 吗？** 普通托管与 Orca 路径都可触发 Codex CLI 按存储会话 ID 续接；原桌面打开窗口即时刷新仍未验证。需要先配置并启用续接，且当前主控空闲。

**新工具没有出现？** 核对安装版本，重新加载插件／MCP 实例。缓存文件替换不会刷新已加载模块的进程。

**Claude 能启动，插件却检测不到？** 当前 Windows 准备检查使用 `claude.cmd`。原生 `claude.exe` 安装形态尚未覆盖这项检测，反馈时说明具体安装方式；不要先更换模型配置。[当前检测实现](../plugins/claude-code/scripts/lib/managed-readiness.mjs)

**从旧插件迁移？** 先停用旧插件，再加载本项目，避免两套同名工具同时操作。已有会话状态路径和兼容环境变量保留，不自动重置。

更多使用方式见 [最佳实践](./最佳实践.md)；开发与发版命令见 [开发指南](./开发指南.md)。
