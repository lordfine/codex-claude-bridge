# 开发指南

## 目录

| 路径 | 职责 |
| --- | --- |
| `.claude-plugin/marketplace.json` | Codex 插件市场入口 |
| `plugins/claude-code/.codex-plugin/` | 插件清单与版本 |
| `plugins/claude-code/scripts/claude-mcp-server.mjs` | 标准输入输出协议与工具分发 |
| `plugins/claude-code/scripts/lib/工具定义.mjs` | 当前公开工具及参数 |
| `plugins/claude-code/scripts/lib/managed-*.mjs` | 状态、工作流、会话、权限与托管执行 |
| `plugins/claude-code/scripts/lib/Orca会话.mjs` | 官方 Orca CLI 适配 |
| `plugins/claude-code/scripts/lib/事件*.mjs` | 事件队列与 Codex 续接 |
| `plugins/claude-code/scripts/lib/协作策略.mjs` | 档位、短交付与稳定快照 |
| `plugins/claude-code/scripts/lib/会话读取.mjs` | 增量关联与只读历史分页 |
| `plugins/claude-code/scripts/lib/本地观察.mjs` | 无模型的本地事件观察 |
| `plugins/claude-code/skills/` | Codex 使用工具的指导 |
| `tests/` | 当前接口回归 |
| `scripts/` | 测试、安装核对与源码打包 |

## 检查

```powershell
npm ci
npm test
node scripts/验证安装接口.mjs plugins/claude-code
node scripts/验证平台终端.mjs
```

默认回归不派发真实模型任务。安装核对读取本机 Claude 版本与终端依赖，不发起模型调用。真实模型任务、终端交互与生产操作应单独规划范围。

工具参数与名称由 `工具定义.mjs` 保存；分发逻辑与实现分开。服务退出只断开协议，托管任务生命周期仍由执行桥接器控制。客户端取消请求不等同于取消 Claude 任务，取消执行使用 `delegate_cancel`。

版本以插件清单为 MCP 服务的事实源，发布时同步根包与运行包版本。既有本地状态路径和 `CC_PLUGIN_CODEX_*` 环境变量维持兼容，不随仓库重命名自动迁移。

## 发版

CI覆盖Windows、Ubuntu与Mac两种架构、Node22／24，并分别执行回归、真实PTY及MCP安装协议核对（Claude命令夹具）。用户设备上的真实回复用 `node scripts/实机验收.mjs --确认运行`，与无模型CI证据分别记录。

运行回归与安装检查，提交干净工作树后建立版本标签。使用打包脚本输出源码 ZIP 与 SHA-256 校验文件，发布到 GitHub Release。包内仅含 Git 跟踪文件，不含依赖、凭据、会话或本机配置。

MIT 许可和上游版权声明保留。目录整理应先核对实际依赖，不删除仍被入口或测试导入的模块。

## 协作技能评估

`skills/consult-claude/` 保留单一短入口，复杂流程放在按需引用中。`evals/evals.json` 保存模拟案例，真实执行输出与旧版快照放在 Git 忽略的 `.技能评估/consult-claude/`。`node scripts/评估协作技能.mjs` 评判已有输出，不调用模型；干净克隆须先收集输出，或显式传评估目录。

评估报告通过 `skill-creator` 自带查看器生成。输出与旧技能快照不应复制进插件缓存；发布和安装使用只含 Git 文件的快照。评估通过率不能代替实机或账单比较。
