# 排队与结果回执

## 排队与压缩

普通任务仍用send。需要保留后续提醒或压缩指令时用delegate_orca(action=enqueue,id,request_id,prompt)，入队只表示持久保存。命令仅支持 `/compact`；不要绕过桥接器用裸Orca发送来规避后台守卫。

queue返回顺序与状态，默认不回传完整指令。启用的本地观察器会在主轮、实际后台任务、人类队列及上一交付处理完后推进；停用时可明确调用dispatch_queue。请求回执不明时只核对confirm_submission，不换ID重发，不继续下一项。

取消尚未发送的项用cancel_queued，传queued_request_id及本次操作的稳定request_id；已发送或不明项不能伪装成未发送取消。

command或排队 `/compact` 必须有官方命令包装UUID与匹配stdout，commandState=completed才证明命令完成；不要求产生普通助手轮。压缩摘要不是新的人类业务指令。普通任务仍须核对userUuid、firstAssistantUuid和completed。

## 后台结果为空

空output文件不证明运行中。先按原任务ID核对真实终态，再用task_result读取已登记子代理的原JSONL；available及原消息UUID才作为已取到结果的依据。unavailable表示尚未取得结论，不能声称运行中、成功或失败。

最多做一次30至60秒增量等待，再检查原日志活动和结果渠道；无新活动则记录阻塞并结束模型轮。不要新开审查代理重做，也不要创建轮询“文件非空”的后台哨兵。没有终态证据不能批量清空真正的PG测试、服务或工具任务。

## 人工已接住交付

diagnose提供pendingEvents的精确id。实际验收后调用delegate_wake(action=pickup,event_ids,resolution)，仅确认已处理的事件。要消除对应needsAcceptance，补task_id、backend、delivery_revision、delivery_snapshot；版本或目录变化则重新验收。CLI仍在运行时不要并行确认同一批。

THREAD_WRITER_BUSY表示本次没有执行，交付保留退避；其他CLI不明回执仍须inspect/resolve。不能用清空队列或新建主控ID解除未知执行。低频无变化时不反复查询，收到明确交付或异常才继续。
