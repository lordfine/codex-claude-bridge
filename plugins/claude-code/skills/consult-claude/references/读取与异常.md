# 读取与异常

`delegate_overview` 汇总登记的执行线。Codex 亲自实现或用户在外部修改时，显式记录其归属与提交，不能套用原 Claude 的阶段。

Orca 的完整系统子代理包装和任务通知继续推进游标，普通引用标签仍保留人类输入边界。旧游标可用 `diagnose` 只读查看；仅可识别通知边界允许 `repair_cursor`，须确认当前人类轮与队列结束，保留控制权，不重发任务。

系统任务通知还按 `origin.kind=task-notification`、`promptSource=system`、`turnOrigin=task_notification` 分类；解析通知头的任务与工具编号，不把结果正文当新指令。旧识别器停在同一条通知上的缓存会重新分类，真实人类输入边界继续保留。

本地命令的回执仅在CLI来源、完整包装与父消息编号都配对时确认完成，不另算人类任务，也不等不存在的模型轮；原命令及其意图保留。后续真实任务继续按正常执行状态判断。

主轮结束、阶段交付、稳定审查与业务验收分开判断。退出状态中的旧 busy/ready 不代表正在执行；父流程出现 `review_blocked` 时核对最新审查，再显式重新审查。

## 历史与实时

会话 ID、执行记录 ID 和 Orca 终端句柄不同。首次按准确 UUID 与原目录确认，不选最近会话。历史查询用 `delegate_sessions(list)` 获取元数据，再用 `delegate_history` 读取所需页；它不会注入指令或暂停原进程。

正文默认最多2400字符，用 `nextCursor` 继续；`changed` 表示源记录替换或缩短，先核对身份后重置游标。工具输出按需 include_tools，常见凭据模式隐藏不是全量保密保证。

Orca 短状态 `revision/after_revision` 与屏幕 `screen_revision`、正文游标互相独立。TUI screen 来源会重绘，不用行范围推断新增正文。先读交付，确有需要再读屏幕或历史。

## 状态含义

- accepted：输入被终端接收，尚不是开工或完成。
- logged：稳定指令标识已与该 UUID 的用户消息关联。
- completed：相应主轮结束证据，不证明所有外部后台进程停止。
- ambiguous／changed／gap：数据不足或状态变化，先停止自动派发。
- cancel requested_unconfirmed：只发了中断请求；未确认范围不继续派发。

普通明确的工具／检查失败交 Claude 自修；重复失败、方向变化、缺少必要输入或身份变化需要主控。等待超时是普通无变化结果；传输、失联、解析和不兼容错误分别处理。工具返回 error.code/operation 时保留原请求 ID，不反复发现整套工具或切换发送通道来碰碰运气。

## 交接

`owner=human` 是临时操作权，绑定仍保留。完成事件带 `humanCursor`；从该游标读新增人类指令并核对对当前目标的影响。Orca 可用 `human_activity` 取 `firstUserCursor` 与完成证据，再用 `transcript` 分页读取；原生用原目录和 UUID 的 `delegate_history`。只读取所需新增部分。

确认人类当前轮、已排队指令、草稿和后台任务均结束后，普通托管用 `delegate_takeover`，Orca 用 `takeover` 并提供 `idle_confirmed=true`、稳定请求 ID。Orca 接续把旧指令记为 `interrupted_by_human`，推进到已处理的人类正文边界，不重发旧任务。未结束则保留观察；禁止把 `release` 用作人类临时操作的处理方式。只有用户在 Codex 明确要求不再使用该会话才解除绑定。

原生 `/交还` 仍可主动交回，不适用于 Orca。需要原窗口权限批准时让用户处理，不替它按确认键。

暂停／取消后记录仍在不代表进程停止。核对模型、工具、子代理和人类队列；不能证明停止时报告不明状态。未被用户要求时不关闭原终端、不清空排队消息。

## 自动续接诊断

先 `delegate_wake(diagnose)` 区分当前 `currentFault`、单记录 `recordFaults` 和旧 `lastRun`。`observerHealth` 显示观察阶段、心跳和是否过期；通知回执只证明调用或操作系统报告，`userSeenConfirmed=false` 不代表用户已看到。CLI 错误摘要有长度限制和常见凭据脱敏，历史未保存详情的异常不能补造。

调度故障保留独立故障 ID。旧运行的 `resolve` 不能解除新调度故障；修复后核对原进程与待办，再决定恢复。诊断、重复观察和故障退避不调用模型。用户停用的自动续接保持停用。

修复后调用 `resolve_fault`，传精确 `fault_id`、已核对的 `resolution` 与 `decision=retry`；有旧 CLI 待核对，先 `inspect/resolve`，再恢复故障。恢复不确认待办、不改变会话控制权，也不自行开启已关闭的配置。只有 `paused=false` 表示调度暂停解除，仍须核对心跳和实际通知回执。

## Orca重启与草稿

句柄随运行时变化。`status` 报 `binding.state=stale` 或观察事件 `binding_stale` 时立即核对；重新 `list`，用原接入 `id`、替代 `terminal_id`、稳定 `request_id` 和 `idle_confirmed=true` 调用 `rebind`。它核对原 UUID 与原目录并保留指令、游标和交付目录；不得同时向旧、新终端发送，也不重新 create。身份不唯一时请用户指定，不挑最近终端。

发现草稿即返回 `draft_blocked` 与来源证据，默认 `source=unknown`。指纹匹配桥接请求也不证明是谁输入。先告知用户内容仍保留，等待用户选择保留、发送或清除，不默默空等、不自动按 Enter/Esc。查看与手工处理不解除会话绑定；清空后有 `draft_cleared` 事件，再核对身份、队列和后台状态。
