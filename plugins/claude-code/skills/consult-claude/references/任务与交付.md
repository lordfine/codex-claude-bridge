# 任务与交付

## 任务模板

```text
目录：原绝对目录
目标：可观察结果
范围：允许修改的模块；必须保持的行为
验收：具体结果和用户要求的定向检查
协作：当前档位；约定子任务／里程碑／完整批次
模型：继承当前配置，或已配置的真实名称
交付：当前交付.md、必要验证证据、未解问题
```

规划一次，不把实现定位再次完整做一遍。可以让 Claude 自主定位与修复常见错误；范围、模型或业务方向变更交给 Codex。不要每个工具调用都提交阶段交付。

## 过程目录

`delegate_coordination(prepare)` 返回 `.协作记录/<任务ID>/` 和三个文件位置。默认排除 Git。任务说明记录约定，当前交付仅保留最新短交付，验证记录保存必要证据；不要写凭据或私密原始日志。

当前交付.md 包含 JSON 代码块：

```json
{
  "task_id": "工具返回的执行记录ID",
  "phase_id": "本任务内唯一的阶段编号",
  "level": "milestone",
  "requires_decision": false,
  "summary": "完成项与改动范围，最多1500字",
  "checks": ["实际执行的检查与结果"],
  "unresolved": [],
  "snapshot": "capture"
}
```

level 可为 subtask、milestone、batch、review、final。`requires_decision=true` 表示必须由主控决定才能继续，三档都及时处理；不要把所有普通进展标成 true。

snapshot=capture 由观察器核验真实工作目录；需要审查的交付须完成当前轮并在两次观察中保持稳定。文件变化后旧快照失效，不能用旧报告验收新代码。检查未执行、跳过或失败时如实记录。

## 返工模板

```text
未满足：具体验收条件
证据：首次真实失败、必要文件／行号、失败前置条件
修复范围：仅本次问题
再验收：需要重复的相关检查
```

先查错误与前置，不先猜端口或配置。一次集中反馈；红绿回放和临时切换旧代码期间不做最终审查。
